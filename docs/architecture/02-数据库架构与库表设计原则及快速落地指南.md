## 核心设计总原则（AI 开发者底层心智）

1. **资产边界法则**：业务主数据（用户、组织、订单、台账）归属传统业务系统；AI 专属库仅存智能体资产（调度状态机、交互快照、向量知识、审计 Trace、映射句柄）。坚决不双写全量业务表，仅存 `biz_id` 弱引用。
2. **三轨分离法则**：
   - **引擎轨（Checkpointer）**：系统底层二进制快照（如 LangGraph Postgres Checkpoint），仅用于图状态断点恢复与引擎调度。   
   - **展示轨（A2UI 快照）**：结构化明文存储，供前端秒级渲染、卡片组装与自包含网络重试。
   - **业务轨（传统 API/ACL）**：工单流转、主数据读写全部通过防腐层接口通信。
3. **隔离与并发法则**：窗口（`session_id`）与执行流（`thread_id`）必须解耦以支持单窗口多工单派生；涉及人机交互（HITL）唤醒时，强制采用乐观锁（`lock_version`）防止并发击穿与状态竞争。

### 1. 会话与运行态控制表：`ai_thread_mappings`

作为状态机的调度大脑，负责将前端 UI 会话、底层状态机线程与外部业务系统打通。

#### 表结构物理定义与字段意图

| **字段名**                              | **物理类型**   | **约束 / 索引**                   | **业务实战作用与避坑指南**                                   |
| --------------------------------------- | -------------- | --------------------------------- | ------------------------------------------------------------ |
| `thread_id`                             | `VARCHAR(64)`  | **PK**                            | **底层引擎的执行线程 ID**。与 LangGraph Checkpoint 中的 `thread_id` 完全对应。建议使用 UUIDv7 或由业务单号派生的唯一编码。 |
| `session_id`                            | `VARCHAR(64)`  | **Index (B-Tree)**                | **前端 UI 对话窗口 ID**。一个窗口可派生多个任务线程（单会话多任务），查历史会话时按此检索。 |
| `biz_order_id`                          | `VARCHAR(64)`  | **Index (B-Tree), Nullable**      | **外部业务系统主键**（如工单号 `OMS-20261105-001`）。前期草稿阶段为 `NULL`，由传统系统生成后回填（延迟落库）。 |
| **`idempotency_key`** *(【新增】底盘1)* | `VARCHAR(64)`  | **Unique Index, Nullable**        | **幂等防护键**。前端生成 UUID 随请求传入，数据库物理级硬阻断弱网重试与用户手抖连击，防止并发重复启动大模型。 |
| `creator_id`                            | `VARCHAR(64)`  | **Index (B-Tree)**                | **发起人工号/用户 ID**。行级权限隔离核心字段，普通用户查询历史列表时强制 `WHERE creator_id = :current_user`。 |
| `creator_dept`                          | `VARCHAR(64)`  | `Nullable`                        | 发起人所属部门/班组（如“腊山运检二班”），用于大屏按部门汇聚统计。 |
| `creator_role`                          | `VARCHAR(32)`  | `NOT NULL`                        | 发起人角色（如 `APPLICANT`），决定状态机的初始准入策略。     |
| `assigned_role`                         | `VARCHAR(32)`  | **Index (B-Tree)**                | **当前协同/待办角色**（如 `DISPATCHER`）。当状态机挂起时，对应角色的审批池看板根据此字段过滤待办。 |
| `status`                                | `VARCHAR(32)`  | **Index (B-Tree)**                | **大业务生命周期状态**。`DRAFT`（草稿中）、`ANALYZING`（审查中）、`WAITING_HUMAN`（人机协同挂起中）、`PERMITTED`（已许可/已完成）、`REJECTED`（已驳回）、`TERMINATED`（已作废）、`ESCALATED`（异常转人工接管）。 |
| `current_node`                          | `VARCHAR(64)`  | `Nullable`                        | **状态机当前停泊节点**（如 `dispatcher_approval`）。前端据此高亮步骤条或流程图节点。 |
| `lock_version`                          | `INTEGER`      | `DEFAULT 1, NOT NULL`             | **CAS 乐观锁版本号**。多审批人并发点击恢复（Resume）时，通过版本号判定冲突，防止重复唤醒状态机。 |
| `operator_id`                           | `VARCHAR(64)`  | `Nullable`                        | 介入审批人工号。                                             |
| `audit_opinion`                         | `TEXT`         | `Nullable`                        | 人工审批意见或驳回原因。                                     |
| `signature_hash`                        | `VARCHAR(128)` | `Nullable`                        | 防篡改防抵赖签名摘要。对“工单核心数据+审批人+时间戳”计算的 SHA-256 或 CA 数字签名。 |
| **`is_archived`** *(【新增】底盘4)*     | `BOOLEAN`      | **Index (B-Tree), DEFAULT FALSE** | **冷热归档标识**。标记是否已完成中间状态裁剪与数据归档，供后台定时清理任务使用。 |
| **`archived_at`** *(【新增】底盘4)*     | `TIMESTAMP`    | `Nullable`                        | **归档时间戳**。记录该任务被移入冷数据或清理检查点的大对象时间。 |
| `created_at`                            | `TIMESTAMP`    | `DEFAULT NOW()`                   | 创建时间。                                                   |
| `updated_at`                            | `TIMESTAMP`    | `DEFAULT NOW()`                   | 最后流转更新时间。                                           |

#### 针对乐观锁并发控制的 SQL 更新实战

在调用状态机恢复（Resume）前，执行原子 CAS 检查：

SQL

```
-- 尝试更新状态并递增版本号，影响行数为 0 则表示已被他人抢审或版本过期
UPDATE ai_thread_mappings 
SET status = 'RUNNING',
    lock_version = lock_version + 1,
    operator_id = 'USER_007',
    audit_opinion = '安措完备，核签通过',
    updated_at = NOW()
WHERE thread_id = '4b810fef-75f9-4b6e-bc79-d966460ed5e8' 
  AND lock_version = 1 
  AND status = 'WAITING_HUMAN';
```

### 1. 向量知识库表：`ai_knowledge_base`（RAG 防幻觉）



#### 字段设计与索引配置



SQL

```
CREATE TABLE ai_knowledge_base (
    id VARCHAR(64) PRIMARY KEY,
    doc_code VARCHAR(64) NOT NULL,               -- 规范/文档编码 (如 "DL-408-2021")
    biz_tag VARCHAR(32) NOT NULL,                -- 业务前置分类标签 (如 "220kV", "变电检修")
    section_title VARCHAR(128),                  -- 章节标题
    content TEXT NOT NULL,                       -- 切片正文
    embedding vector(1536) NOT NULL,             -- 向量字段 (对应 text-embedding-v3 等模型)
    is_active BOOLEAN DEFAULT TRUE NOT NULL,     -- 有效性软删除 (版本废止时置 false)
    doc_version VARCHAR(32) DEFAULT 'v1.0',      -- 文档版本号
    created_at TIMESTAMP DEFAULT NOW()
);

-- 1. 业务标签前置 B-Tree 索引 (极重要：元数据前置过滤加速)
CREATE INDEX idx_knowledge_biz_tag ON ai_knowledge_base(biz_tag);
CREATE INDEX idx_knowledge_is_active ON ai_knowledge_base(is_active);

-- 2. HNSW 余弦相似度专用索引 (亚毫秒级向量召回)
CREATE INDEX idx_knowledge_embedding_hnsw ON ai_knowledge_base 
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);
```

#### 高性能元数据预过滤检索 SQL



SQL

```
-- 先通过 B-Tree 索引过滤 active 和业务标签，再执行向量余弦距离搜索 (<=>)
SELECT id, doc_code, section_title, content, 
       1 - (embedding <=> :query_vector) AS similarity
FROM ai_knowledge_base
WHERE is_active = TRUE 
  AND biz_tag = '220kV'
ORDER BY embedding <=> :query_vector
LIMIT 3;
```

### 2. 智能体元数据与版本表：`ai_agent_configs`（Prompt 灰度管理）



当系统支持多 Agent，或需要动态调整 System Prompt 时引入此表，使历史工单具备可复现性。   

SQL

```
CREATE TABLE ai_agent_configs (
    id VARCHAR(64) PRIMARY KEY,
    agent_key VARCHAR(64) NOT NULL,              -- Agent 唯一键 (如 "safety_auditor")
    version VARCHAR(32) NOT NULL,                -- 版本号 (如 "v2.1.0")
    system_prompt TEXT NOT NULL,                 -- 系统提示词正文
    model_name VARCHAR(64) NOT NULL,             -- 默认绑定模型
    temperature NUMERIC(3, 2) DEFAULT 0.1,       -- 采样温度
    tools_enabled JSONB,                         -- 启用的工具列表 ["query_weather", "check_ground_line"]
    is_default BOOLEAN DEFAULT FALSE,            -- 是否为当前正式生效版本
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE UNIQUE INDEX uq_agent_version ON ai_agent_configs(agent_key, version);
```

- **关联方式**：在 `ai_thread_mappings` 中增加 `agent_config_id VARCHAR(64)`。即使半年后 Prompt 经过多次迭代，回溯排查某笔工单时，依然可以查出当时使用的具体配置。   

### 3. 长期记忆与事实偏好表：`ai_user_memories`（个性化 Agent）



解决单会话 Token 上限限制，跨 Session 沉淀用户画像与偏好。   

SQL

```
CREATE TABLE ai_user_memories (
    id VARCHAR(64) PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL,                -- 绑定的用户/调度员工号
    memory_type VARCHAR(32) NOT NULL,            -- PREFERENCE (偏好) | FACT (事实) | PROFILE (画像)
    memory_key VARCHAR(64) NOT NULL,             -- 记忆标签 (如 "frequent_substation")
    memory_value JSONB NOT NULL,                 -- 提炼沉淀的事实 JSON
    confidence NUMERIC(3, 2) DEFAULT 1.0,        -- 置信度 (0.00 ~ 1.00)
    last_accessed_at TIMESTAMP DEFAULT NOW(),    -- 记忆衰减算法触发时间
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_user_memory_lookup ON ai_user_memories(user_id, memory_type);
```

- **工作机制**：在每次新建 `thread_id` 时，系统先根据 `user_id` 捞取高频偏好（如“习惯停电操作前优先确认接地刀闸”），将其组装为 System Prompt 的前置 Context。   

### 4. 批处理与异步任务表：`ai_batch_jobs`（离线任务流）



用于支撑离线批量检修单审核、大批量台账数据智能清洗等耗时场景。   

SQL

```
CREATE TABLE ai_batch_jobs (
    job_id VARCHAR(64) PRIMARY KEY,
    job_name VARCHAR(128) NOT NULL,
    creator_id VARCHAR(64) NOT NULL,
    status VARCHAR(32) DEFAULT 'PENDING',        -- PENDING | RUNNING | COMPLETED | FAILED
    total_count INTEGER DEFAULT 0,               -- 需处理总条目数
    processed_count INTEGER DEFAULT 0,           -- 已完成条目数
    failed_count INTEGER DEFAULT 0,              -- 失败条目数
    input_file_url TEXT,                         -- 待处理源文件 (Excel/ZIP)
    output_file_url TEXT,                        -- 汇总输出文件 (Excel/PDF)
    error_summary TEXT,                          -- 错误概要
    created_at TIMESTAMP DEFAULT NOW(),
    finished_at TIMESTAMP
);
```

- **派生机制**：一个 `job_id` 在后台解析出 100 条待审任务后，由任务调度器（如 Celery / ARQ）生成 100 个独立的 `thread_id`，并发调用 Agent 逐条处理，进度递增回写 `processed_count`。

### 操作细节拆解

1. **步骤 1：梳理业务归属权（系统边界确认）**

   - **动作**：与业务方明确用户账号、业务工单存放在哪里[cite: 6]。如果存在外部系统（如电网 OMS/PMS），在表结构中仅将 `biz_order_id` 设为 `VARCHAR(64)` 弱引用，编写 ACL 防腐适配器交互，严禁在 AI 库中建全量业务主表[cite: 6]。

2. **步骤 2：明确人机协同（HITL）闸口**

   - **动作**：画出流程图，标出哪些节点大模型能自主流转（如“安规初审”），哪些节点必须人工核签（如“调度员审批”）[cite: 6]。存在人工节点的，状态机必须支持中断挂起（`interrupt`）[cite: 6]。
   - **【新增】传输层保活细节**：针对长流程思考或长耗时挂起，在 FastAPI 的 SSE 响应生成器中内置心跳机制（每隔 15 秒输出一次 `:ping\n\n` 空白帧），防止经过反向代理（如 Nginx、SLB）时因 60 秒无数据传输而被强制掐断连接。

3. **步骤 3：定义控制表 `ai_thread_mappings`**

   - **动作**：以模板为基准，加入 `thread_id`、`session_id`、`assigned_role`，以及 CAS 乐观锁 `lock_version`[cite: 6]。
   - **【新增】底盘增量**：同时加入唯一索引的 `idempotency_key`（解决用户连击和网关弱网重发），以及 `is_archived`、`archived_at`（支撑冷热归档）。

4. **步骤 4：定义交互表 `ai_chat_messages`**

   - **动作**：规划前端需要的交互组件类型（卡片还是文字），在表中预留 `card_payload`（JSONB）与 `retry_payload`（JSONB）[cite: 6]。
   - **【新增】底盘增量**：加入 `is_sanitized` 布尔字段。在 Python 数据入库管道层，通过正则或脱敏规则库将手机号、核心 IP、身份证过滤替换后再存盘，并置 `is_sanitized = True`。

5. **步骤 5：定义追踪表 `ai_execution_traces`**

   - **动作**：设置字段记录 `prompt_tokens`、`completion_tokens`、`latency_ms` 及 `tool_calls`[cite: 6]。

6. **步骤 6：配置 pgvector 知识库表**

   - **动作**：确定 Embedding 模型维度（如 1536），编写建表 DDL，挂载 `HNSW` 余弦相似度索引，配置 `is_active` 与业务分类 `biz_tag`[cite: 6]。

7. **步骤 7：选装 N 类扩展表**

   - **动作**：根据需求决策链，评估是否需要 Prompt 灰度管理（`ai_agent_configs`）或跨 Session 记忆（`ai_user_memories`）[cite: 6]。

8. **步骤 8：配置物理隔离双连接池**

   - **动作**：在 `database.py` 中分设 SQLAlchemy 引擎（业务 CRUD）与原生 `psycopg` 连接池（`AsyncPostgresSaver` 专享），并为 psycopg 连接池配置 `kwargs={"autocommit": True}`。   

9. **步骤 9：跨平台与环境防御性编码**

   - **动作**：在应用入口和单测脚本头部注入平台判定[cite: 6]：

     Python

     ```
     if sys.platform == "win32":
         asyncio.set_event_loop_policy(asyncio.WindowsSelectorEventLoopPolicy())
     ```

10. **步骤 10：FastAPI Lifespan 生命周期闭环**

    - **动作**：在 `main.py` 的 `lifespan` 上下文管理器中，启动时执行 `await checkpointer_manager.init_pool()`，退出时执行 `close_pool()` 和 `async_engine.dispose()`[cite: 6]。
    - **【新增】快照归档与 TTL 逻辑**：编写定时脚本或后台任务，定期检索 `status IN ('PERMITTED', 'REJECTED')` 且完结超过 30 天的工单，将 `is_archived` 置为 `True`，并执行 `DELETE FROM checkpoint_blobs WHERE thread_id = ...` 剔除底层的二进制大快照，释放数据库物理存储。

import uuid
from datetime import datetime
from sqlalchemy import String, Text, DateTime, Integer, Boolean, Numeric, Index
from sqlalchemy.dialects.postgresql import JSONB
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column
from pgvector.sqlalchemy import Vector

class Base(DeclarativeBase):
    pass

# ==========================================
# 1. 会话映射与运行态控制表 (核心调度中枢)
# ==========================================
class AIThreadMapping(Base):
    __tablename__ = "ai_thread_mappings"

    thread_id: Mapped[str] = mapped_column(String(64), primary_key=True)
    session_id: Mapped[str] = mapped_column(String(64), index=True, nullable=False)
    biz_order_id: Mapped[str | None] = mapped_column(String(64), index=True, nullable=True) # 外部业务单号 (弱引用)
    
    # 【新增底盘能力 1】：幂等防护 (唯一索引硬阻断重复点击与重试)
    idempotency_key: Mapped[str | None] = mapped_column(String(64), unique=True, index=True, nullable=True)

    # 权限与多角色隔离体系
    creator_id: Mapped[str] = mapped_column(String(64), index=True, nullable=False)
    creator_dept: Mapped[str | None] = mapped_column(String(64), nullable=True)
    creator_role: Mapped[str] = mapped_column(String(32), nullable=False)
    assigned_role: Mapped[str] = mapped_column(String(32), index=True, default="APPLICANT")
    
    # 状态机生命周期控制
    status: Mapped[str] = mapped_column(String(32), index=True, default="DRAFT")
    current_node: Mapped[str | None] = mapped_column(String(64), nullable=True)
    
    # 并发安全与审计防抵赖
    lock_version: Mapped[int] = mapped_column(Integer, default=1, nullable=False)
    operator_id: Mapped[str | None] = mapped_column(String(64), nullable=True)
    audit_opinion: Mapped[str | None] = mapped_column(Text, nullable=True)
    signature_hash: Mapped[str | None] = mapped_column(String(128), nullable=True)

    # 【新增底盘能力 4】：冷热数据生命周期与归档管理 (TTL)
    is_archived: Mapped[bool] = mapped_column(Boolean, default=False, index=True)
    archived_at: Mapped[datetime | None] = mapped_column(DateTime, nullable=True)
    
    created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow)
    updated_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)


# ==========================================
# 2. 交互载荷与卡片快照表 (A2UI 极速回显)
# ==========================================
class AIChatMessage(Base):
    __tablename__ = "ai_chat_messages"

    id: Mapped[str] = mapped_column(String(64), primary_key=True, default=lambda: str(uuid.uuid4()))
    thread_id: Mapped[str] = mapped_column(String(64), index=True, nullable=False)
    role: Mapped[str] = mapped_column(String(16), nullable=False)
    kind: Mapped[str] = mapped_column(String(16), default="text")
    content: Mapped[str | None] = mapped_column(Text, nullable=True)
    
    # A2UI 卡片与自包含重试载荷
    card_type: Mapped[str | None] = mapped_column(String(32), nullable=True)
    card_payload: Mapped[dict | None] = mapped_column(JSONB, nullable=True)
    retry_payload: Mapped[dict | None] = mapped_column(JSONB, nullable=True)

    # 【新增底盘能力 3】：安全脱敏审计标记
    is_sanitized: Mapped[bool] = mapped_column(Boolean, default=False, nullable=False)
    
    created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow)


# ==========================================
# 3. 运行审计与可观测 Trace 表
# ==========================================
class AIExecutionTrace(Base):
    __tablename__ = "ai_execution_traces"

    id: Mapped[str] = mapped_column(String(64), primary_key=True, default=lambda: str(uuid.uuid4()))
    thread_id: Mapped[str] = mapped_column(String(64), index=True, nullable=False)
    node_name: Mapped[str] = mapped_column(String(64), nullable=False)
    model_name: Mapped[str] = mapped_column(String(64), nullable=False)
    
    prompt_tokens: Mapped[int] = mapped_column(Integer, default=0)
    completion_tokens: Mapped[int] = mapped_column(Integer, default=0)
    total_cost: Mapped[float] = mapped_column(Numeric(10, 4), default=0.0)
    latency_ms: Mapped[int] = mapped_column(Integer, nullable=False)
    
    tool_calls: Mapped[dict | None] = mapped_column(JSONB, nullable=True)
    error_log: Mapped[str | None] = mapped_column(Text, nullable=True)
    
    created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow)


# ==========================================
# 4. 向量知识库表 (RAG 防幻觉支持)
# ==========================================
class AIKnowledgeBase(Base):
    __tablename__ = "ai_knowledge_base"

    id: Mapped[str] = mapped_column(String(64), primary_key=True, default=lambda: str(uuid.uuid4()))
    doc_code: Mapped[str] = mapped_column(String(64), index=True, nullable=False)
    biz_tag: Mapped[str] = mapped_column(String(32), index=True, nullable=False)
    section_title: Mapped[str | None] = mapped_column(String(128), nullable=True)
    content: Mapped[str] = mapped_column(Text, nullable=False)
    embedding: Mapped[list[float]] = mapped_column(Vector(1536), nullable=False)
    
    is_active: Mapped[bool] = mapped_column(Boolean, default=True, index=True)
    doc_version: Mapped[str] = mapped_column(String(32), default="v1.0")
    created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow)

# 构建 HNSW 余弦相似度专用索引
Index(
    "idx_knowledge_embedding_hnsw",
    AIKnowledgeBase.embedding,
    postgresql_using="hnsw",
    postgresql_with={"m": 16, "ef_construction": 64},
    postgresql_ops={"embedding": "vector_cosine_ops"}
)
